Beta 2.1 is version `0.3.1`, build `4`. The planned release tag is
`v0.3.1-beta.1`, with assets `LocalOCR-Studio-0.3.1-4.zip` and
`LocalOCR-Studio-0.3.1-4.sha256`.

This file describes the release candidate. The exact release commit, ZIP

## Desktop app first

LocalOCR Studio keeps the default one-document workflow and the opt-in,
review-first sequential desktop batch. Originals are never overwritten.
Searchable PDFs and batch outputs are written separately, with numbered names
when a preferred output already exists.

Beta 2.1 adds an app-owned offline Help Center covering desktop use, batch,
outputs, privacy, Local Intelligence, agent connection, troubleshooting, FAQ,
and exact app version/build.

## Local Intelligence

For one processed document, LocalOCR can summarize, suggest a title/category/
tags, or extract requested fields with page evidence. Results are temporary and
non-destructive. Desktop batch remains OCR-only.

- Apple Foundation Models uses `SystemLanguageModel.default` on eligible Macs.
  Apple does not expose a more specific installed model name or version.
- LocalOCR can detect and qualify supported Ollama and LM Studio models through
  exact IPv4 or IPv6 loopback routes.
- Detection is not selection. External local runtimes require qualification,
  explicit model selection, and the displayed acknowledgment.
- Remote, relayed, wildcard, generic OpenAI-compatible, and locality-ambiguous
  endpoints are refused.
- LocalOCR never silently switches providers and has no cloud fallback or
  Private Cloud Compute path.

## Agent connection and MCP

The app can detect supported Codex and Claude Code installations. It shows the
exact helper path and scope and requires confirmation before running the
client's own MCP add/remove command. Other MCP clients receive copy-only stdio
instructions.

The bundle contains exactly three arm64 native helpers:

- `localocr` — CLI and MCP consent management;
- `localocr-mcp` — local stdio MCP server; and
- `localocr-model-bridge` — bounded loopback bridge for qualified Ollama and
  LM Studio operations, not an MCP server.

`localocr-mcp` exposes exactly nine document tools. All nine require the
versioned external-data acknowledgment because the connected client or its AI
provider may send tool arguments and results outside this Mac. The MCP server
has no HTTP listener or network transport.

## Privacy boundary

Apple Vision OCR, PDF processing, cache, and Apple Foundation Models processing
remain on the Mac. A selected Ollama or LM Studio route sends required OCR text
only to the acknowledged harness over verified loopback; that harness may keep
its own logs or history. A connected MCP client's handling is controlled by
that client/provider, not LocalOCR.

## Compatibility and open release gates

- Apple silicon and macOS 14 or later are required.
- Apple Foundation Models requires macOS 26 or later plus Apple Intelligence
  eligibility, enablement, model readiness, and supported language.
- The candidate is compiled with stable Xcode 26.6 (`17F113`), Swift 6, arm64,
  and deployment target macOS 14.0.
- Future Apple beta compatibility is not guaranteed.
- Developer ID signing with Hardened Runtime, notarization, stapling,
  Gatekeeper, downloaded-package verification, and exact-build target-Mac
  acceptance remain required before publication.

## Known limitations

- No Intel, Windows, or Linux support.
- No batch history or guided language/settings wizard.
- Desktop batch performs OCR only; it does not run Local Intelligence.
- Generic MCP clients use copy-only setup instructions.
- OCR and model output can contain errors; keep original documents and review
  substantive results.
