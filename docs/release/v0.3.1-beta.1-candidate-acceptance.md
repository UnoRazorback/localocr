## Packaged helper boundary

The release-native build produced exactly three arm64 helpers:

- `localocr`
- `localocr-mcp`
- `localocr-model-bridge`

Artifact policy accepts only Apple/system dependencies and approved system
RPATHs. The bridge policy permits only explicit IPv4 and IPv6 loopback URLs
for Ollama on port 11434 and LM Studio on port 1234, disables proxy use,
rejects redirects, and caps responses at 1 MiB. Generic, remote, relayed, or
locality-ambiguous OpenAI-compatible endpoints fail closed.

## Consent and privacy acceptance

Using an isolated private test profile, an MCP intelligence request before
acknowledgment was refused with
`external_data_acknowledgment_required`. A first receipt attempt under `/tmp`
was also refused as `insecureFilesystemState`. Acceptance succeeded only after
the private profile used a real, symlink-free, mode-0700 Application Support
directory and both required acknowledgments were supplied.

The isolated profile was disposable. Real user preferences and agent
configuration were not changed.

## Runtime-network observation

A discarded first observation selected the wrong scope and is not evidence.
The corrected observation sampled the exact running MCP process during an
Apple Foundation Models summary and found no TCP or UDP handles.

During Ollama qualification, each observed `localocr-model-bridge` process had
only a loopback connection to `127.0.0.1:11434`; no non-loopback socket was
observed. LM Studio remained blocked because its actual local runtime exposed
peer/remote evidence, so no document content was sent through it.
